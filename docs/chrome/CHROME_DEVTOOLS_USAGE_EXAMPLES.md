# Chrome DevTools MCP 實際使用範例

## 適用於 Claude Code 環境

---

## 📌 使用方式

1. 選擇下方合適的場景
2. **整個複製** 該場景的提示文字
3. 在 Claude Code 中 **貼上** 執行
4. 等待 Claude 完成驗證並回報結果

## 場景 1: 驗證 taifex-query F14 資料爬蟲

### 複製以下內容到 Claude Code:

```
我需要驗證 taifex-query F14 模組的資料爬蟲是否正常運作。

請使用 Chrome DevTools 幫我完成以下驗證：

【第 1 步】打開目標網站
- 網址: https://www.taifex.com.tw/cht/3/totalTableDate
- 等待頁面完全載入（通常 3 秒以內）

【第 2 步】視覺驗證
- 確認頁面顯示「三大法人」表格
- 確認「外資」行存在
- 確認可以看到以下 3 個欄位：
  ✓ 多方未平倉口數 (期望值: 297,271)
  ✓ 空方未平倉口數 (期望值: 473,500)
  ✓ 多空淨額 (期望值: -176,229)

【第 3 步】Network 監控
- 打開 DevTools (F12)
- 切換到 Network 標籤
- 重新整理頁面 (Ctrl+R)
- 查看所有網路請求
- 確認沒有紅色數字 (400+ 錯誤)
- 特別檢查 XHR 或 Fetch 請求是否成功

【第 4 步】Console 檢查
- 切換到 Console 標籤
- 查看是否有紅色錯誤訊息
- 記錄任何 JavaScript 錯誤

【第 5 步】拍攝證據
- 拍攝正常顯示的數據表格截圖
- 如果有錯誤，拍攝 Network tab 的失敗請求截圖
- 如果有錯誤，拍攝 Console 的錯誤訊息截圖

【期望結果清單】
□ 頁面 3 秒內載入
□ 外資未平倉數據表格完整可見
□ Network 所有請求都是 200-299 狀態
□ Console 沒有紅色錯誤
□ 看到的數據與上面的期望值相符

【報告格式】
請告訴我：
1. ✅ 頁面是否正常載入？
2. ✅ 資料表格是否完整顯示？
3. ✅ Network 是否有錯誤？
4. ✅ Console 是否有錯誤？
5. 💾 附上相應的截圖
6. 📝 如有問題，詳細描述

謝謝！
```

## 場景 2: 驗證 DGtech 網站單個頁面

### 複製以下內容到 Claude Code:

```
請幫我驗證 DGtech 網站的 [頁面名稱] 頁面。

【步驟】

1️⃣ 打開頁面
- 在瀏覽器中打開: http://localhost:8000/[頁面URL]
- 例如首頁: http://localhost:8000/index.html
- 等待頁面完全載入

2️⃣ 視覺檢查 (逐項檢查)
- [ ] 頁面標題正確顯示
- [ ] 所有圖片都已正確載入（沒有損壞圖片符號）
- [ ] 文字清晰可讀
- [ ] 頁面排版正確（沒有錯位）
- [ ] 所有顏色符合設計稿
- [ ] 如果是響應式，測試不同螢幕寬度

3️⃣ 功能測試 (如有互動元素)
- [ ] 點擊所有導航連結 → 是否跳轉正確？
- [ ] 如果有表單，嘗試輸入並提交 → 是否有反應？
- [ ] 如果有按鈕，點擊它們 → 是否觸發正確的動作？
- [ ] 如果有下拉菜單，展開並選擇 → 是否正常？

4️⃣ DevTools 檢查
a) 打開 DevTools (按 F12)
b) Console 標籤：
   - 有紅色錯誤嗎？[是/否]
   - 如有，記錄完整的錯誤訊息
   - 有黃色警告嗎？[是/否]
c) Network 標籤：
   - 重新整理頁面 (Ctrl+R)
   - 有紅色的請求嗎 (5xx 或連接失敗)？[是/否]
   - 有黃色的請求嗎 (4xx 客戶端錯誤)？[是/否]
   - 如有，記錄失敗的檔案名稱

5️⃣ 拍攝截圖（證據）
- 整個頁面的正常顯示截圖
- Console 的截圖（如果有錯誤）
- Network 的截圖（如果有失敗的請求）

6️⃣ 效能檢查 (可選)
- 頁面載入時間大約是多少？ __ 秒
- 是否感覺到任何卡頓或延遲？

【匯總報告】
請按以下格式告訴我結果：

頁面: [M00/M01/M02...]
URL: http://localhost:8000/...
時間: [現在時間]

視覺效果: ✅ 正常 / ❌ 有問題
功能測試: ✅ 全部通過 / ❌ 有問題
Console: ✅ 無錯誤 / ❌ 有錯誤 [列出]
Network: ✅ 無失敗 / ❌ 有失敗 [列出]
整體評級: ✅ PASS / ❌ FAIL

問題詳情 (如有):
1. [問題 1]
2. [問題 2]

謝謝！
```

## 場景 3: 表單驗證

### 複製以下內容到 Claude Code:

```
請幫我驗證 [表單名稱] 表單的驗證邏輯。

【目標網址】
http://localhost:8000/[表單頁面URL]

【驗證步驟】

1️⃣ 必填欄位驗證
- 打開表單
- 不填任何欄位，直接點「提交」或按 Enter
- 觀察是否出現「此欄位必填」或類似的提示
- 記錄出現的提示訊息

2️⃣ 格式驗證 (針對各類型欄位)
a) 如果有 Email 欄位：
   - 輸入：abc (無效格式)
   - 點提交
   - 是否顯示格式錯誤提示？ [是/否]

b) 如果有密碼欄位：
   - 輸入：123 (過短)
   - 點提交
   - 是否顯示密碼過弱或過短的提示？ [是/否]

c) 如果有電話欄位：
   - 輸入：abcd (無效電話)
   - 點提交
   - 是否顯示格式錯誤提示？ [是/否]

3️⃣ 成功提交測試
- 填入所有必需欄位的有效值
- 點提交
- DevTools > Network: 觀察是否有 API 請求發出
- 請求的 HTTP 狀態是什麼？ [200/400/500/其他]
- 提交後頁面發生什麼？ [重定向/顯示成功訊息/留在原頁面/其他]

4️⃣ DevTools 監控
- 打開 Console
- 重複上述所有測試步驟
- 記錄任何紅色錯誤訊息
- 特別注意 XHR/Fetch 的錯誤

5️⃣ 截圖證據
- 驗證錯誤的截圖
- 成功提交時的截圖
- Network 請求的截圖
- Console 錯誤的截圖 (如有)

【匯總報告格式】

表單: [表單名稱]
URL: http://localhost:8000/...
時間: [現在時間]

必填驗證: ✅ PASS / ❌ FAIL
Email 格式驗證: ✅ PASS / ❌ FAIL / N/A
密碼驗證: ✅ PASS / ❌ FAIL / N/A
電話驗證: ✅ PASS / ❌ FAIL / N/A
成功提交: ✅ PASS / ❌ FAIL
Console 錯誤: ✅ 無 / ❌ 有 [列出]

整體結果: ✅ 全部通過 / ❌ 有失敗項目

失敗項目詳情:
1. [項目] - [問題描述]
2. [項目] - [問題描述]

謝謝！
```

## 場景 4: API 整合驗證

### 複製以下內容到 Claude Code:

```
請幫我驗證 API: [API 名稱/端點] 的整合狀況。

【API 詳情】
- 端點: [POST/GET/PUT/DELETE] /api/[端點路徑]
- 預期會在: [用戶執行什麼操作時觸發]
- 例如: 點擊「提交」按鈕時

【驗證步驟】

1️⃣ 準備環境
- 打開目標頁面: http://localhost:8000/[頁面]
- 打開 DevTools (F12)
- 切換到 Network 標籤

2️⃣ 觸發 API 呼叫
- [執行會觸發該 API 的操作，例如：點擊提交按鈕]
- 在 Network 標籤中查找對應的請求
- 要找的是: URL 包含 [api 端點路徑] 的請求

3️⃣ 檢查請求詳情
點擊該請求，查看以下資訊：
- 【Headers】標籤：
  ✓ HTTP 方法: [GET/POST/PUT/DELETE]
  ✓ 狀態碼: [200/400/500/其他]
  ✓ 有沒有 Authorization 或認證標頭？
  ✓ Content-Type 是什麼？

- 【Payload】或【Request】標籤：
  ✓ 請求的資料格式是什麼？ (JSON/Form-data/其他)
  ✓ 送出的資料有哪些欄位？ (列出)
  ✓ 欄位值是否正確？

- 【Response】標籤：
  ✓ 伺服器的回應是什麼？ (複製完整內容)
  ✓ 回應的格式是 JSON 嗎？
  ✓ 有錯誤訊息嗎？

4️⃣ 驗證期望結果
- [ ] HTTP 狀態碼是 200 或 201 (成功) 還是 4xx/5xx (失敗)？
- [ ] 回應資料符合預期格式嗎？
- [ ] 如果有錯誤，錯誤訊息清晰嗎？

5️⃣ Console 檢查
- 打開 Console 標籤
- 有紅色錯誤嗎？ [是/否]
- 如有，記錄完整錯誤訊息

6️⃣ 拍攝截圖
- Network 標籤中該 API 請求的完整截圖
- Request Headers 的截圖
- Request Payload 的截圖
- Response 的截圖
- Console 錯誤的截圖 (如有)

【匯總報告格式】

API: [API 端點]
方法: [GET/POST/PUT/DELETE]
時間: [現在]

【請求驗證】
HTTP 方法: ✅ 正確 / ❌ 錯誤
請求資料: ✅ 正確 / ❌ 錯誤 [說明]
認證: ✅ 正確 / ❌ 缺失 / N/A

【回應驗證】
狀態碼: __ (期望: 200/201)
回應格式: ✅ JSON / ❌ 其他 [說明]
回應資料: ✅ 正確 / ❌ 錯誤 [說明]

【整體結果】
✅ API 正常運作 / ❌ 有問題

問題詳情:
[如有問題，詳細說明]

謝謝！
```

## 📌 使用技巧

### ✅ 最佳實踐
1. **複製完整** - 不要只複製部分提示
2. **逐步執行** - 按照步驟順序執行
3. **詳細截圖** - 遇到問題時一定要拍截圖
4. **完整報告** - 用提供的格式回報結果

### ❌ 常見錯誤
- ❌ 忘記打開 DevTools (F12)
- ❌ 忘記切換到 Network 或 Console 標籤
- ❌ 沒有等待頁面完全載入就開始檢查
- ❌ 本機伺服器沒啟動 (localhost:8000)

### 🎯 優化提示
- 使用書籤保存常用提示
- 創建一個「驗證清單」文件
- 定期執行回歸測試
- 在開發前後都驗證一次
