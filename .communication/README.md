# 🔗 角色間通訊系統

> **版本**: 1.0
> **建立日期**: 2025-12-07
> **用途**: 實現 Claude 多討論組角色間的非同步通訊

---

## 📖 系統說明

此通訊系統允許不同 Claude 討論組（開發專員、測試專員、文件專員、架構專員）透過共享檔案進行非同步通訊。

### 運作原理

1. **訊息發送**: 角色完成工作後，將訊息寫入接收者的收件匣
2. **訊息接收**: 接收者啟動時自動檢查收件匣，處理未讀訊息
3. **訊息回覆**: 處理完畢後，將回覆寫入發送者的收件匣
4. **訊息歸檔**: 已處理的訊息移至「已處理訊息」區塊

### 對於 Claude 角色

#### 啟動時自動執行

每個角色的啟動卡應包含以下邏輯：

```markdown
## 💬 通訊協定（每次啟動自動執行）

1. **讀取收件匣**
   - 檔案路徑：`.communication/{your_role}_inbox.md`
   - 檢查「未讀訊息」區塊

2. **處理未讀訊息**
   - 如果有標記為 `[ ]` 的訊息：
     - 讀取訊息內容
     - 執行訊息中的待辦事項
     - 標記為已讀 `[x]`
     - 如需回覆，寫入發送者的收件匣
     - 將訊息移至「已處理訊息」區塊

3. **回報狀態**
   - 向使用者報告：「已處理 X 則訊息」或「無新訊息」

4. **繼續等待指令**
   - 處理完收件匣後，等待使用者的新指令
```

#### 發送訊息

當需要通知其他角色時：

```python
# 1. 讀取訊息範本
# 2. 填寫訊息內容
# 3. 寫入接收者的收件匣
# 4. 通知使用者：「已發送訊息至 [角色]」
```

## 📝 訊息格式規範

### 標準訊息格式

```markdown
### [ ] YYYY-MM-DD HH:MM - 來自 [角色標記] [角色名稱]

> **訊息 ID**: msg_YYYYMMDD_HHMMSS
> **優先級**: 🔴 高 / 🟡 中 / 🟢 低
> **類型**: 📋 任務請求 / 💬 資訊通知 / ❓ 問題詢問 / ✅ 完成回報

**主旨**: [簡短描述]

**內容**:
[詳細說明]

**相關檔案**:
- `path/to/file.py`

**請接收者執行**:
- [ ] [待辦事項 1]
- [ ] [待辦事項 2]

**回覆方式**:
請回覆至 `.communication/[發送者]_inbox.md`

---
```

### 訊息狀態

- `[ ]` - 未讀/待處理
- `[x]` - 已讀/已處理

### 優先級

- 🔴 **高**：需要立即處理（阻擋其他工作）
- 🟡 **中**：正常優先級（按順序處理）
- 🟢 **低**：可延後處理（資訊通知）

### 訊息類型

- 📋 **任務請求**：需要接收者執行特定任務
- 💬 **資訊通知**：僅通知，無需回覆
- ❓ **問題詢問**：需要接收者回答問題
- ✅ **完成回報**：回報任務完成狀態

## 🎯 最佳實踐

### 訊息發送原則

1. **明確主旨**：主旨應簡短明確，讓接收者一眼看出重點
2. **完整內容**：提供足夠的背景資訊與上下文
3. **清楚待辦**：使用 checklist 列出明確的待辦事項
4. **附上檔案**：列出所有相關檔案路徑
5. **設定優先級**：根據緊急程度設定適當優先級

### 訊息處理原則

1. **優先處理高優先級訊息**
2. **完成後立即標記為已讀**
3. **需要回覆的訊息必須回覆**
4. **定期清理已處理訊息**（移至歷史區塊）

### 回覆原則

1. **引用原訊息 ID**：便於追蹤
2. **回答所有問題**：確保完整回覆
3. **提供具體結果**：避免模糊回覆
4. **附上驗證證明**：測試結果、截圖等

## 📊 系統優勢

### 相較於「您手動傳話」的優勢

| 項目 | 手動傳話 | 通訊系統 |
|------|---------|---------|
| 效率 | 需要您每次傳遞訊息 | 自動檢查處理 |
| 記錄 | 訊息分散在對話中 | 集中管理，易追蹤 |
| 完整性 | 可能遺漏細節 | 完整的結構化訊息 |
| 追蹤 | 難以追蹤任務狀態 | 清楚標記待辦/已完成 |
| 歷史 | 難以回溯歷史通訊 | 完整的訊息歷史 |

### 相較於「完全自動化」的限制

由於 Claude Code 的技術限制，此系統無法做到：
- ❌ 自動觸發其他討論組（仍需您開啟）
- ❌ 即時通訊（非同步通訊）
- ❌ 推送通知

但已實現：
- ✅ 自動檢查收件匣
- ✅ 自動處理訊息
- ✅ 結構化訊息管理
- ✅ 任務狀態追蹤

## ❓ 常見問題

### Q1: 訊息會自動觸發其他討論組嗎？

**A**: 不會。您仍需要手動切換討論組。但切換後，角色會自動檢查並處理收件匣訊息。

### Q2: 如果忘記檢查收件匣怎麼辦？

**A**: 角色的啟動卡包含自動檢查機制，只要您開啟討論組，就會自動執行。

### Q3: 訊息會不會遺失？

**A**: 不會。所有訊息都儲存在檔案中，即使討論組關閉也不會遺失。

### Q4: 如何知道有新訊息？

**A**:
- 方法 1: 角色啟動時會主動報告「已處理 X 則訊息」
- 方法 2: 您可以隨時查看 `.communication/` 目錄中的收件匣檔案

### Q5: 可以批次處理多則訊息嗎？

**A**: 可以。角色會依優先級順序處理所有未讀訊息。
