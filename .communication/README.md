## �📖 系統說明

### 運作原理

此通訊系統允許不同 Claude 討論組透過共享檔案進行非同步通訊：

1. **訊息發送** → 角色完成工作後，將訊息寫入接收者的收件匣
2. **訊息接收** → 接收者啟動時自動檢查收件匣，處理未讀訊息
3. **訊息回覆** → 處理完畢後，將回覆寫入發送者的收件匣
4. **訊息歸檔** → 已處理的訊息移至「已處理訊息」區塊

### 檔案結構

```
.communication/
├── README.md                  # 本文件（系統說明）
├── MESSAGE_TEMPLATE.md        # 訊息範本
├── dev_inbox.md              # 💻 開發專員收件匣
├── test_inbox.md             # 🧪 測試專員收件匣
├── doc_inbox.md              # 📚 文件專員收件匣
└── arch_inbox.md             # 🏗️ 架構專員收件匣
```

    ↓

### 對於 Claude 角色

#### 啟動時自動執行

每個角色啟動時應：

1. **讀取收件匣** → `.communication/{your_role}_inbox.md`
2. **處理未讀訊息** → 標記為 `[ ]` 的訊息
3. **回報狀態** → 「已處理 X 則訊息」或「無新訊息」
4. **繼續等待指令** → 處理完收件匣後，等待使用者的新指令

> 💡 **詳細操作步驟請參考**: `dev/啟動卡_通訊協定.md`

#### 發送訊息

當需要通知其他角色時：

1. 讀取 `MESSAGE_TEMPLATE.md` 範本
2. 填寫訊息內容（時間、優先級、類型、主旨、待辦事項等）
3. 寫入接收者的收件匣（插入「未讀訊息」區塊頂部）
4. 通知使用者：「已發送訊息至 [角色]」

## 🎯 最佳實踐

### 訊息發送原則

1. ✅ **明確主旨** - 讓接收者一眼看出重點
2. ✅ **完整內容** - 提供足夠的背景資訊與上下文
3. ✅ **清楚待辦** - 使用 checklist 列出明確的待辦事項
4. ✅ **附上檔案** - 列出所有相關檔案路徑
5. ✅ **設定優先級** - 根據緊急程度設定適當優先級

### 訊息處理原則

1. ✅ 優先處理高優先級訊息
2. ✅ 完成後立即標記為已讀
3. ✅ 需要回覆的訊息必須回覆
4. ✅ 定期清理已處理訊息

### 回覆原則

1. ✅ 引用原訊息 ID（便於追蹤）
2. ✅ 回答所有問題（確保完整回覆）
3. ✅ 提供具體結果（避免模糊回覆）
4. ✅ 附上驗證證明（測試結果、截圖等）

### 相較於手動傳話

| 項目 | 手動傳話 | 通訊系統 |
|------|---------|---------|
| 效率 | 需要您每次傳遞訊息 | 自動檢查處理 |

| 追蹤 | 難以追蹤任務狀態 | 清楚標記待辦/已完成 |
| 歷史 | 難以回溯歷史通訊 | 完整的訊息歷史 |

### 技術限制

由於 Claude Code 的技術限制，此系統無法做到：
- ❌ 自動觸發其他討論組（仍需您手動開啟）
- ❌ 即時通訊（非同步通訊）
- ❌ 推送通知

但已實現：
- ✅ 自動檢查收件匣
- ✅ 自動處理訊息
- ✅ 結構化訊息管理
- ✅ 任務狀態追蹤

## ❓ 常見問題

### Q1: 訊息會自動觸發其他討論組嗎？
**A**: 不會。您仍需要手動切換討論組。但切換後，角色會自動檢查並處理收件匣訊息。

### Q2: 如果忘記檢查收件匣怎麼辦？
**A**: 角色的啟動卡包含自動檢查機制，只要您開啟討論組，就會自動執行。

### Q3: 訊息會不會遺失？
**A**: 不會。所有訊息都儲存在檔案中，即使討論組關閉也不會遺失。

### Q4: 如何知道有新訊息？
**A**: 
- 方法 1: 角色啟動時會主動報告「已處理 X 則訊息」
- 方法 2: 您可以隨時查看 `.communication/` 目錄中的收件匣檔案

### Q5: 可以批次處理多則訊息嗎？
**A**: 可以。角色會依優先級順序處理所有未讀訊息。
