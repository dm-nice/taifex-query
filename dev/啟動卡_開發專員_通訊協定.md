# 💬 開發專員通訊協定補充

> **用途**: 補充開發專員啟動卡，加入自動通訊檢查機制
> **版本**: 1.0
> **建立日期**: 2025-12-07

---

## 🔔 每次啟動自動執行（在處理使用者指令前）

### 1. 檢查收件匣

```markdown
**檔案路徑**: `.communication/dev_inbox.md`

**檢查步驟**:
1. 讀取 dev_inbox.md
2. 尋找「未讀訊息」區塊中所有標記為 `[ ]` 的訊息
3. 如果有未讀訊息 → 執行步驟 2
4. 如果無未讀訊息 → 向使用者報告「無新訊息」，繼續等待指令
```

### 2. 處理未讀訊息

```markdown
**處理流程**:

對每則未讀訊息：

1. **讀取訊息內容**
   - 訊息 ID
   - 優先級
   - 類型
   - 主旨
   - 內容
   - 相關檔案
   - 待辦事項

2. **根據類型處理**

   **📋 任務請求**:
   - 執行訊息中的所有待辦事項
   - 讀取相關檔案
   - 完成任務
   - 準備回覆內容

   **❓ 問題詢問**:
   - 研究問題
   - 提供詳細答案
   - 準備回覆內容

   **💬 資訊通知**:
   - 閱讀並記錄資訊
   - 無需回覆

   **✅ 完成回報**:
   - 閱讀報告
   - 確認結果
   - 根據需要決定是否回覆

3. **回覆訊息**（如需要）
   - 使用 `.communication/MESSAGE_TEMPLATE.md` 範本
   - 填寫回覆內容
   - 引用原訊息 ID
   - 寫入發送者的收件匣

4. **更新收件匣**
   - 將訊息標記從 `[ ]` 改為 `[x]`
   - 將已處理訊息移至「已處理訊息」區塊
   - 更新「最後檢查」時間戳

5. **向使用者報告**
   - 報告已處理的訊息數量
   - 簡述處理結果
   - 如有回覆，說明已回覆至哪個角色
```

### 3. 回報狀態

```markdown
**回報格式**:

如果有處理訊息：
```
📬 收件匣檢查完成
- 已處理 {N} 則訊息

處理摘要：
1. [訊息主旨] - [處理結果]
2. [訊息主旨] - [處理結果]

回覆狀態：
- 已回覆 {角色}: [簡述內容]
```

如果無訊息：
```
📬 收件匣檢查完成 - 無新訊息
```
```

## 📤 發送訊息流程

### 當需要通知其他角色時

```markdown
**步驟**:

1. **確定接收者**
   - 💻 開發專員 → `dev_inbox.md`
   - 🧪 測試專員 → `test_inbox.md`
   - 📚 文件專員 → `doc_inbox.md`
   - 🏗️ 架構專員 → `arch_inbox.md`

2. **準備訊息**
   - 讀取 `.communication/MESSAGE_TEMPLATE.md`
   - 填寫必要欄位：
     - 時間戳
     - 訊息 ID（格式：msg_YYYYMMDD_HHMMSS）
     - 優先級（🔴高/🟡中/🟢低）
     - 類型（📋任務/💬通知/❓詢問/✅回報）
     - 主旨
     - 內容
     - 相關檔案
     - 待辦事項（如果是任務請求）
     - 回覆方式

3. **寫入收件匣**
   - 讀取接收者的 inbox 檔案
   - 將新訊息插入「未讀訊息」區塊的頂部
   - 寫回檔案

4. **通知使用者**
   ```
   📤 已發送訊息至 [角色]
   - 主旨: [訊息主旨]
   - 優先級: [優先級]
   - 類型: [類型]
   ```
```

## 🎯 使用場景範例

### 場景 1: 完成開發後通知測試專員

```markdown
**情境**: 開發專員完成 F01 測試腳本優化

**動作**:
1. 完成程式碼修改
2. 準備訊息給測試專員
3. 寫入 `test_inbox.md`
4. 通知使用者

**訊息內容**:
```
### [ ] 2025-12-07 21:00 - 來自 💻 開發專員

> **訊息 ID**: msg_20251207_210000
> **優先級**: 🟡 中
> **類型**: 📋 任務請求

**主旨**: F01 測試腳本 v2.0 已優化完成，請驗證

**內容**:
已完成 F01 自動化測試腳本的通過率計算邏輯優化。

**相關檔案**:
- `dev/f01_package/test_f01_auto.py` (v2.0)

**請測試專員執行**:
- [ ] 執行測試腳本並確認通過率為 100%
- [ ] 回覆驗證結果

**回覆方式**:
請回覆至 `.communication/dev_inbox.md`
```
```

### 場景 2: 收到測試專員的驗證回報

```markdown
**情境**: 開發專員啟動時發現收件匣有測試專員的回覆

**動作**:
1. 自動讀取 `dev_inbox.md`
2. 發現來自測試專員的訊息
3. 讀取驗證結果
4. 標記訊息為已讀
5. 向使用者報告

**報告內容**:
```
📬 收件匣檢查完成 - 已處理 1 則訊息

處理摘要：
1. F01 測試腳本 v2.0 驗證完成 - 全部通過
   - 來自: 🧪 測試專員
   - 結果: 測試通過率 100%，所有項目符合預期
   - 建議: 可作為未來新模組範本

已確認測試結果，F01 測試腳本 v2.0 驗證通過。
```
```

- [ ] 已讀取收件匣
- [ ] 已處理所有未讀訊息

- [ ] 已移動至「已處理訊息」區塊
