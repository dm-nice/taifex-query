# 💬 Claude 角色間通訊協定

> **用途**: 所有 Claude 角色（開發、測試、架構、文件專員）的通訊操作指南
> **版本**: 2.0（通用版）
> **建立日期**: 2025-12-09

---

## 🔔 每次啟動自動執行（在處理使用者指令前）

### 1. 檢查收件匣

**檔案路徑**:
- 💻 開發專員 → `.communication/dev_inbox.md`
- 🧪 測試專員 → `.communication/test_inbox.md`
- 🏗️ 架構專員 → `.communication/arch_inbox.md`
- 📚 文件專員 → `.communication/doc_inbox.md`

**檢查步驟**:
1. 讀取你的收件匣檔案
2. 尋找「未讀訊息」區塊中所有標記為 `[ ]` 的訊息
3. 如果有未讀訊息 → 執行步驟 2
4. 如果無未讀訊息 → 向使用者報告「無新訊息」，繼續等待指令

---

### 2. 處理未讀訊息

**處理流程**:

對每則未讀訊息：

#### 2.1 讀取訊息內容
- 訊息 ID
- 優先級（🔴高/🟡中/🟢低）
- 類型（📋任務/💬通知/❓詢問/✅回報）
- 主旨
- 內容
- 相關檔案
- 待辦事項

#### 2.2 根據類型處理

**📋 任務請求**:
- 執行訊息中的所有待辦事項
- 讀取相關檔案
- 完成任務
- 準備回覆內容

**❓ 問題詢問**:
- 研究問題
- 提供詳細答案
- 準備回覆內容

**💬 資訊通知**:
- 閱讀並記錄資訊
- 無需回覆

**✅ 完成回報**:
- 閱讀報告
- 確認結果
- 根據需要決定是否回覆

#### 2.3 回覆訊息（如需要）
- 使用 `.communication/MESSAGE_TEMPLATE.md` 範本
- 填寫回覆內容
- 引用原訊息 ID
- 寫入發送者的收件匣

#### 2.4 更新收件匣
- 將訊息標記從 `[ ]` 改為 `[x]`
- 將已處理訊息移至「已處理訊息」區塊
- 更新「最後檢查」時間戳

#### 2.5 向使用者報告
- 報告已處理的訊息數量
- 簡述處理結果
- 如有回覆，說明已回覆至哪個角色

---

### 3. 回報狀態

**如果有處理訊息**:
```
📬 收件匣檢查完成
- 已處理 {N} 則訊息

處理摘要：
1. [訊息主旨] - [處理結果]
2. [訊息主旨] - [處理結果]

回覆狀態：
- 已回覆 {角色}: [簡述內容]
```

**如果無訊息**:
```
📬 收件匣檢查完成 - 無新訊息
```

## 📤 發送訊息流程

### 當需要通知其他角色時

#### 步驟 1: 確定接收者

| 接收角色 | 收件匣檔案 |
|---------|-----------|
| 💻 開發專員 | `.communication/dev_inbox.md` |
| 🧪 測試專員 | `.communication/test_inbox.md` |
| 📚 文件專員 | `.communication/doc_inbox.md` |
| 🏗️ 架構專員 | `.communication/arch_inbox.md` |

#### 步驟 2: 準備訊息

讀取 `.communication/MESSAGE_TEMPLATE.md`，填寫必要欄位：

- **時間戳**: YYYY-MM-DD HH:MM
- **訊息 ID**: msg_YYYYMMDD_HHMMSS
- **優先級**: 🔴高 / 🟡中 / 🟢低
- **類型**: 📋任務請求 / 💬資訊通知 / ❓問題詢問 / ✅完成回報
- **主旨**: 簡短描述
- **內容**: 詳細說明
- **相關檔案**: 檔案路徑列表
- **待辦事項**: checklist（如果是任務請求）
- **回覆方式**: 指定回覆收件匣

#### 步驟 3: 寫入收件匣

1. 讀取接收者的 inbox 檔案
2. 將新訊息插入「未讀訊息」區塊的**頂部**
3. 寫回檔案

#### 步驟 4: 通知使用者

```
📤 已發送訊息至 [角色]
- 主旨: [訊息主旨]
- 優先級: [優先級]
- 類型: [類型]
```

## 🎯 使用場景範例

### 場景 1: 開發完成後通知測試專員

**情境**: 開發專員完成 F01 模組開發

**動作**:
1. 完成程式碼修改
2. 準備訊息給測試專員
3. 寫入 `test_inbox.md`
4. 通知使用者

**訊息範例**:
```markdown
### [ ] 2025-12-09 16:00 - 來自 💻 開發專員

> **訊息 ID**: msg_20251209_160000
> **優先級**: 🟡 中
> **類型**: 📋 任務請求

**主旨**: F01 模組開發完成，請進行測試

**內容**:
已完成 F01 模組的開發，實現了資料抓取與格式化功能。

**相關檔案**:
- `modules/f01_fetcher.py`
- `dev/f01_package/f01_fetcher_開發規範書.md`

**請測試專員執行**:
- [ ] 執行功能測試
- [ ] 驗證輸出格式
- [ ] 回覆測試結果

**回覆方式**:
請回覆至 `.communication/dev_inbox.md`
```

---

### 場景 2: 測試專員回報測試結果

**情境**: 測試專員完成測試，回報給開發專員

**動作**:
1. 完成測試驗證
2. 準備回覆訊息
3. 寫入 `dev_inbox.md`
4. 通知使用者

**訊息範例**:
```markdown
### [ ] 2025-12-09 17:00 - 來自 🧪 測試專員

> **訊息 ID**: msg_20251209_170000
> **優先級**: 🟢 低
> **類型**: ✅ 完成回報
> **回覆**: msg_20251209_160000

**主旨**: F01 模組測試完成 - 全部通過

**內容**:
已完成 F01 模組的測試，所有測試項目均通過：
- ✅ 功能測試：正常
- ✅ 錯誤處理：正常
- ✅ 輸出格式：符合 v5.0 規範

**測試結果**:
- 測試通過率：100% (9/9)
- 無發現問題

**建議**:
可以正式上線。

**回覆方式**:
無需回覆（僅通知）
```

### 場景 3: 架構專員詢問技術方案

**情境**: 架構專員需要開發專員評估技術方案

**訊息範例**:
```markdown
### [ ] 2025-12-09 10:00 - 來自 🏗️ 架構專員

> **訊息 ID**: msg_20251209_100000
> **優先級**: 🔴 高
> **類型**: ❓ 問題詢問

**方案 A**: 使用 requests + HTML 解析

- 缺點: 可能有限制

**方案 B**: 使用 Selenium 瀏覽器自動化
- 優點: 功能完整
- 缺點: 執行較慢，需要額外依賴

**請開發專員評估**:
- [ ] 測試兩種方案的可行性
- [ ] 評估優缺點
- [ ] 提供技術建議
- [ ] 預估開發時間

**回覆方式**:
請回覆至 `.communication/arch_inbox.md`

**期限**: 2025-12-09 18:00
```
