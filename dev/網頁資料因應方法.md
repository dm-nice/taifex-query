# TAIFEX 網頁資料抓取因應對策與限制

本文件彙整 F01~F04 模組在抓取台灣期貨交易所 (TAIFEX) 資料時，所遇到的限制、陷阱與標準因應方式。

## 📊 模組行為總表

| 模組 | 功能描述 | 資料來源 (API) | **日期參數行為** | **潛在風險** |
|-----|----------|---------------|----------------|------------|
| **F01** | 外資-未平倉-淨額 | `futContractsDate` | ❌ **無視** (強制回傳最新) | 無法回測歷史數據 |
| **F02** | 外資-未平倉-多方 | `futContractsDate` | ❌ **無視** (強制回傳最新) | 無法回測歷史數據 |
| **F03** | 外資-未平倉-空方 | `futContractsDate` | ❌ **無視** (強制回傳最新) | 無法回測歷史數據 |
| **F04** | 台指期-收盤價 | `futDailyMarketReport` | ✅ **支援** (可指定日期) | 需注意與 F01~03 的時間同步問題 |

---

## 🚨 問題一：日期參數無效 (F01, F02, F03)

### 現象
- URL 為 `https://www.taifex.com.tw/cht/3/futContractsDate?queryDate=YYYY/MM/DD`。
- 無論 `queryDate` 填寫哪一天（例如 `2020/01/01`），網頁永遠只回傳 **「最近一個交易日」** 的數據。

### 影響
1. **數據不一致**：若與支援指定日期的模組 (F04) 混用，容易發生「張飛打岳飛」（F04 抓歷史，F01 抓今日）的狀況。
2. **無法回測**：這些模組無法用於產生歷史報表或回測策略。

### 因應對策
- **整合執行時**：執行指令 **不應指定日期參數**，或必須意識到 F01~F03 回傳的是今日數據。
- **程式實作**：雖然程式碼介面 `fetch(date)` 接受日期參數，但在規範書中明確標註「API 限制：無視日期」。
- **未來解法**：若需歷史數據，需改用「期貨每日交易行情下載」CSV 專區，而非使用此 HTML 表格頁面。

## 🚨 問題二：HTML 欄位名稱陷阱 (F04)

### 現象
- 網頁上顯示的欄位是「最後成交價」，但在 HTML 原始碼或 Pandas 解析時，可能變成具有**不規則空白**的字串，例如 `最後 成交價`。

### 影響
- 導致程式找不到欄位，誤以為該欄不存在。
- 觸發錯誤的備援邏輯（例如 F04 誤抓取到「結算價」），導致數值些微偏差，難以第一時間察覺。

### 因應對策
- **模糊匹配**：在尋找欄位時，不要只比對單一字串。應建立關鍵字清單。
    ```python
    # ❌ 錯誤寫法
    if col == '最後成交價': ...

    # ✅ 正確寫法
    keywords = ['最後成交價', '最後 成交價', 'Close', 'Last Price']
    if any(k in col_name for k in keywords): ...
    ```
- **除錯工具**：遇到「找不到欄位」或「數值怪怪的」時，務必先 Dump 完整的一行資料 (`Row Data`) 來檢查欄位名稱與數值對應關係。

## 💡 建議開發守則

1. **先檢查列印**：開發新抓取模組時，第一步先寫小腳本 (Inspection Script) 印出 `df.columns` 和 `df.iloc[0]`，確認實際欄位名稱。
2. **時間同步**：進行跨模組計算（如 `F01 = F02 - F03`）時，確認所有模組的資料來源日期是否一致。
3. **備援警示**：若程式使用了備援欄位（如找不到成交價改抓結算價），理應在 Log 中發出警告，避免誤用。
