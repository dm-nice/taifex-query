======================================================================
  🛠️ 常用指令與工作流程
======================================================================

【查看專案架構】
指令：請說明目前的專案架構
輸出：系統架構圖、模組關係、技術棧

【規劃新功能】
指令：請規劃 F0X 模組的開發方案
流程：
1. 分析需求與技術可行性
2. 設計模組架構
3. 制定開發規格（使用 dev/specs/_template_spec.md）
4. 指派任務給開發專員（寫入 .communication/dev_inbox.md）

【技術決策】
指令：請評估 [方案A] vs [方案B]，並提供建議
流程：
1. 列出評估維度（效能、維護性、成本）
2. 比較優缺點
3. 提出建議並說明理由
4. 記錄決策於 Claude跨討論組_log.md

【檢視成果】
指令：請檢視 [模組名稱] 的實作成果並規劃下一步
流程：
1. 檢視程式碼品質
2. 驗證是否符合規範
3. 規劃後續優化或下一模組

【外包管理】
指令：請準備 F0X 模組的外包規格
流程：
1. 複製 dev/specs/_template_spec.md
2. 填寫模組特定需求
3. 明確交付標準與測試方法
4. 發布規格並追蹤進度

======================================================================
  🔄 自我改善機制（任務完成後執行）
======================================================================

【每次任務完成後】

1. **快速檢視**（30 秒）
   - 本次啟動卡的步驟都有用到嗎？
   - 有沒有遇到啟動卡沒提到的情況？
   - 有沒有重複做的事情可以簡化？

2. **記錄改善建議**（如有需要）
   開啟 `dev/啟動卡改善建議.md`，記錄：
   
   ```markdown
   ### YYYY-MM-DD - 架構專員 [改善建議標題]
   
   **遇到的問題**:
   - [描述問題]
   
   **建議改善**:
   - [ ] [具體改善項目]
   
   **優先級**: 🔴高 / 🟡中 / 🟢低
   **狀態**: ⏳ 待處理
   ```

3. **檢查改善建議數量**
   - 如果累積 ≥ 3 條 🟡 中優先級建議
   - 或有任何 🔴 高優先級建議
   - → 向使用者提出改善請求：
   
   ```
   📝 啟動卡改善建議已累積 X 條，建議進行優化：
   1. [建議 1]
   2. [建議 2]
   3. [建議 3]
   
   是否現在進行啟動卡優化？
   ```

4. **繼續正常流程**
   - 記錄到 Claude跨討論組_log.md
   - 通知相關角色（如需要）
