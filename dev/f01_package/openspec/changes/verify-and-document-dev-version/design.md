## 🔧 3. 代碼可維護性優化方案

### 3.1 類型提示完善

**目前狀況**:
```python
def format_f01_output(
    date: str,
    status: str,
    data: Optional[Dict] = None,
    error: Optional[str] = None,
    timestamp: Optional[str] = None,
    context: Optional[Dict] = None
) -> str:
```

**改進方向**:
- ✅ 使用 `TypedDict` 定義 `data` 的精確結構
  ```python
  class ForeignDataDict(TypedDict):
      net_position: int
      long_position: int
      short_position: int
      source: str
  ```
- ✅ 所有函數返回值都有明確類型標註
- ✅ 複雜返回值使用 TypedDict 定義

### 3.2 日誌策略統一

**目前狀況**:
```python
logger.info(f"正在抓取 {date} 的資料...")
logger.debug("偵測到 MultiIndex 表頭")
logger.exception("未預期的錯誤")
```

**改進方向**:
- ✅ **日誌級別統一**
  - `logger.info`: 主要操作開始/完成
  - `logger.debug`: 流程分支點、格式偵測
  - `logger.warning`: 可恢復的異常、降級處理
  - `logger.error`: 無法恢復的異常
  
- ✅ **日誌上下文統一**
  - 每條日誌都包含足夠的上下文（date, step, error_type）
  - 敏感信息過濾（URL 參數、完整 traceback）
  
- ✅ **日誌格式化**
  ```python
  logger.error(
      f"[F01] {date} 抓取失敗",
      extra={
          "error": error_msg,
          "step": "html_parsing",
          "timeout_seconds": 30
      }
  )
  ```

### 3.3 代碼結構優化

**優化建議**:

| 項目 | 目前狀況 | 改進方案 |
|------|--------|--------|
| 常數定義 | 分散在代碼中 | 集中定義常數類 |
| HTTP 配置 | 硬編碼在 fetch() | 提取為配置類 |
| 表格欄位搜尋 | 邏輯相似但重複 | 統一為 FieldFinder 類 |
| 異常處理 | 5 個 except 塊 | 統一為自定義異常類 |

**不破壞現有結構的改進**:
- ✅ 添加配置類（不改變現有函數）
- ✅ 添加輔助類（不改變現有函數）
- ✅ 保留現有函數簽名（向後兼容）
