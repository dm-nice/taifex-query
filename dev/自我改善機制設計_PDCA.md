# 🔄 Claude 角色自我改善機制設計

> **目的**: 讓 Claude 角色在每次執行任務後，自動檢視並改善啟動卡和通訊協定  
> **版本**: 1.0  
> **建立日期**: 2025-12-10

---

## 📋 核心概念

### 改善循環（PDCA）

```
執行任務 → 記錄問題 → 分析改善點 → 更新文件 → 下次執行時應用
```

---

## 🎯 改善觸發時機

### 時機 1: 任務完成後（每次必做）
在記錄到 `Claude跨討論組_log.md` 之前，先執行改善檢查。

### 時機 2: 遇到問題時（即時改善）
- 啟動卡指示不清楚
- 收件匣格式混亂
- 通訊協定有遺漏

### 時機 3: 定期回顧（每週一次）
使用者可以要求：「請檢視並改善啟動卡」

---

## ✅ 自我改善檢查清單

### 啟動卡改善檢查

每次任務完成後，問自己：

#### 1. 啟動流程
- [ ] 啟動步驟是否都執行了？
- [ ] 有沒有遺漏的步驟？
- [ ] 有沒有多餘的步驟？
- [ ] 步驟順序是否合理？

#### 2. 文件引用
- [ ] 引用的文件路徑是否正確？
- [ ] 有沒有新的重要文件需要加入？
- [ ] 有沒有過時的文件需要移除？

#### 3. 常用指令
- [ ] 常用指令是否涵蓋了實際使用情境？
- [ ] 有沒有新的常用模式需要加入？
- [ ] 指令範例是否清楚？

#### 4. 工作記錄格式
- [ ] 記錄格式是否符合實際使用？
- [ ] 有沒有遺漏的重要欄位？
- [ ] 格式是否易於閱讀？

### 收件匣改善檢查

#### 1. 訊息格式
- [ ] 訊息格式是否一致？
- [ ] 優先級設定是否合理？
- [ ] 待辦事項是否清楚？

#### 2. 處理流程
- [ ] 訊息處理是否順暢？
- [ ] 有沒有處理不當的訊息？
- [ ] 回覆是否及時且完整？

#### 3. 歸檔管理
- [ ] 已處理訊息是否及時移動？
- [ ] 歷史訊息是否需要清理？

---

## 🔧 實作方式

### 方案 1: 在啟動卡中加入「任務結束檢查」

在每個角色的啟動卡最後加入：

```markdown
【任務完成後的自我改善】

每次完成任務並記錄到 Claude跨討論組_log.md 後：

1. **檢視本次工作流程**
   - 啟動卡的步驟是否都有用到？
   - 有沒有遇到啟動卡沒提到的情況？
   - 有沒有重複做的事情可以簡化？

2. **記錄改善建議**
   在 `dev/啟動卡改善建議.md` 中記錄：
   ```markdown
   ### YYYY-MM-DD - [角色] 改善建議
   
   **遇到的問題**:
   - [描述問題]
   
   **建議改善**:
   - [ ] [具體改善項目]
   
   **優先級**: 🔴高 / 🟡中 / 🟢低
   ```

3. **累積 3 條建議後，主動提出改善**
   向使用者報告：
   ```
   📝 啟動卡改善建議已累積 3 條，建議進行優化：
   1. [建議 1]
   2. [建議 2]
   3. [建議 3]
   
   是否現在進行改善？
   ```

4. **執行改善**
   - 更新啟動卡
   - 更新通訊協定（如需要）
   - 清空改善建議清單
```

### 方案 2: 建立改善建議檔案

建立 `dev/啟動卡改善建議.md`，讓各角色記錄改善建議：

```markdown
# 啟動卡改善建議

## 💻 開發專員

### 2025-12-10 - 收件匣檢查流程不夠明確
**遇到的問題**: 不確定要先處理高優先級還是按時間順序
**建議改善**: 
- [ ] 在啟動卡中明確說明：優先處理 🔴 高優先級訊息
**優先級**: 🟡 中

### 2025-12-09 - 常用指令缺少測試相關
**遇到的問題**: 經常需要執行測試，但啟動卡沒有測試指令範例
**建議改善**:
- [ ] 加入「執行測試」常用指令
**優先級**: 🟢 低

## 🧪 測試專員

（測試專員的改善建議）

## 🏗️ 架構專員

（架構專員的改善建議）
```

### 方案 3: 使用 AI 自動分析（進階）

在 `Claude跨討論組_log.md` 中加入「反思」欄位：

```markdown
### 2025-12-10 (X) - [任務主題]

> **執行者**: 💻 開發專員 Claude

#### 完成事項
...

#### 🔍 反思與改善
**本次工作流程順暢度**: ⭐⭐⭐⭐☆ (4/5)

**遇到的問題**:
- 啟動卡中沒有提到如何處理多個高優先級訊息

**改善建議**:
- [ ] 在啟動卡中加入「優先級相同時，按時間順序處理」的說明

**是否需要更新啟動卡**: 是 / 否
```

---

## 📊 改善建議的優先級判斷

| 優先級 | 觸發條件 | 處理時機 |
|--------|---------|---------|
| 🔴 高 | 影響工作執行、造成錯誤 | 立即改善 |
| 🟡 中 | 影響效率、造成困擾 | 累積 3 條後改善 |
| 🟢 低 | 優化體驗、錦上添花 | 累積 5 條後改善 |

## 🎯 整合到現有啟動卡

### 在啟動卡最後加入

```markdown
======================================================================
  🔄 自我改善機制（任務完成後執行）
======================================================================

【每次任務完成後】

1. **快速檢視**（30 秒）
   - 本次啟動卡的步驟都有用到嗎？
   - 有沒有遇到啟動卡沒提到的情況？

2. **記錄改善建議**（如有需要）
   - 開啟 `dev/啟動卡改善建議.md`
   - 記錄問題與建議
   - 設定優先級

3. **檢查改善建議數量**
   - 如果累積 ≥ 3 條 🟡 中優先級建議
   - 或有任何 🔴 高優先級建議
   - → 向使用者提出改善請求

4. **繼續正常流程**
   - 記錄到 Claude跨討論組_log.md
   - 通知相關角色（如需要）
```

```

「本次任務中，我發現啟動卡沒有提到如何處理緊急 Bug 修復的流程。

📝 新增改善建議：
- 問題：緊急 Bug 修復流程不明確
- 建議：在啟動卡中加入「緊急 Bug 修復」常用指令
- 優先級：🟡 中

目前累積改善建議：2 條（還差 1 條會提醒您）」

```

1. 🟡 加入緊急 Bug 修復流程
2. 🟡 明確收件匣優先級處理順序
3. 🟡 補充測試指令範例

是否現在進行啟動卡優化？」
```

## 🔧 實作步驟

### 步驟 1: 建立改善建議檔案
建立 `dev/啟動卡改善建議.md`

### 步驟 2: 更新所有啟動卡
在每個角色的啟動卡最後加入「自我改善機制」區塊

### 步驟 3: 更新通訊協定
在 `dev/啟動卡_通訊協定.md` 中加入改善機制說明

### 步驟 4: 測試運行
- 執行一次完整任務
- 記錄改善建議
- 驗證機制是否運作

---

## ✅ 預期效果

1. **持續優化** - 啟動卡和通訊協定會隨著使用越來越完善
2. **問題追蹤** - 所有問題都有記錄，不會遺漏
3. **優先處理** - 重要問題會立即改善，小問題累積後處理
4. **減少干擾** - 不會每次都要求改善，避免打斷工作流程
